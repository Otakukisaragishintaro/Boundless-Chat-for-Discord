## 新功能

- 新增可选的本地翻译缓存，默认关闭。开启后，成功译文会写入 Discord 应用私有目录中的 SQLite 数据库；再次遇到相同原文和相同完整翻译配置时，优先命中缓存，避免重复调用翻译 API、节省 Token 与等待时间。
- 本地缓存支持独立开关、容量设置、已保存条目数显示和手动清空；容量可设为 1–1,000,000 条，默认上限 100,000 条，并按最近使用情况淘汰旧条目。
- 缓存只保存原文计算出的 SHA-256 键和译文，不保存原文、API 密钥或额外请求头。缓存数据保留在 Discord 应用私有存储中；清除 Discord 应用数据或卸载 Discord 会删除它。
- 将本地缓存和 API/请求参数分别整理为独立设置子页面，提供页面内应用入口；缓存容量在缓存关闭时也可编辑。
- 为未来接入其他聊天宿主建立 platform/common 与 platform/discord 适配层目录和职责文档；本轮不迁移现有 Hook 类，也不改变运行时 Hook 路径。

## 修复与改进

- 修复缓存条目数同步：新译文持久化后及时更新设置页计数；删除、清空及容量淘汰后同步实际数量。
- 新增 Discord 到模块设置页的单向缓存计数 IPC。通道只传递条目数量，不传递原文、译文、缓存键或 API 凭据；模块端验证调用方身份。
- 修复缓存运行时热重载时计数监听和 IPC 执行器的生命周期管理，避免重载后计数不再更新或遗留后台线程。
- 缓存读取或数据库不可用时回退到正常 API 翻译，不阻断消息翻译；缓存配置默认关闭，不影响未启用缓存的用户。
- 统一设置主页和子页面的系统窗口 Insets 处理，修复冷启动进入缓存/API 子页面时顶部内容被标题栏遮挡的问题。
- 更新 GitHub Actions 到支持 Node.js 24 的版本，移除 checkout、Java 与 Gradle 构建步骤使用旧版 Actions 产生的弃用警告。

## 注意事项

- 本地缓存是可选功能，需在“本地翻译缓存”页面主动开启；开启前已经显示的旧译文不会自动补写，开启后成功完成的新翻译才会进入缓存。
- 缓存命中依赖原文内容及完整翻译配置版本；修改模型、协议、提示词、目标语言等配置后，不会错误复用旧配置下的译文。
- 缓存计数显示的是 SQLite 持久化条目数，不包括仅存在于进程内的临时内存缓存。清空操作会删除本地持久化译文缓存。
- 其他聊天宿主的接入目录目前只是架构准备，不代表已经支持其他应用；每个宿主仍需单独完成适配和设备验证。
